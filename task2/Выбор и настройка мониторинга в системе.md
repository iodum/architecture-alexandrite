# Мотивация

Мониторинг поможет быстрее замечать проблемы, значит проблема раньше будет исправлена и будет меньше потерянных заказов.

Мониторинг поможет:

- оперативно выявлять и устранять сбои в системе
- находить зависшие заказы
- автоматически отправлять уведомления при наступлении критической ситуации

## Выбор подхода к мониторингу

Метод RED подходит больше всего, т.к. необходимо работу сервисов (в том числе API), очередей, запросы к БД.

1. RED – для API и очередей, т.к. позволяет отслеживать нагрузку API, количество ошибок в запросах или потерянных
   сообщений
2. USE – для сереверов и БД, т.к. поможет отслеживать использование ресурсов

## Метрики

| Метрика                                            | Зачем нужна                        | Ярлыки                 |
|----------------------------------------------------|------------------------------------|------------------------|
| Number of dead-letter-exchange letters in RabbitMQ | Выявление потерянных сообщений     | queue_name, error_type |
| Number of messages in flight                       | Выявление переполненности очередей | queue_name             |
| Number of requests (RPS) (MES/CRM/Shop)            | Нагрузка на API                    | endpoint               |
| CPU % (MES/CRM/Shop)                               | Загрузка серверов                  |                        |
| Number of connections (MES/CRM db)                 | Загруженность БД                   |                        |
| Response time (latency) for MES API                | Скорость ответа                    | endpoint               |
| Size of S3 storage                                 | Контроль хранилища 3D-моделей      |                        |
| Number of HTTP 500 (MES/CRM/Shop)                  | Ошибки сервера	                    | endpoint, error_code   |

## Показатели насыщенности

| Метрика                                      |                               | Действие                           |
|----------------------------------------------|-------------------------------|------------------------------------|
| Latency > 5s                                 | Замедление работы системы     | Уведомление команде                |
| Number of dead-letter-exchange > 10 в минуту | Поломка в обработке сообщений | Завести тикет, уведомление команде |
| CPU > 80%                                    | Высокая загруженность         | Добавить инстанс                   |
